自动化任务：量化交易学习与 jingni-trader 优化
============================================================
调度时间：每天 06:00（北京时间）
Cron 表达式：0 6 * * *
时区：Asia/Shanghai
============================================================

你的任务是定期联网学习量化交易领域的开源项目，并将学习成果应用于 jingni-trader 项目的优化思考与验证。

执行流程：

1. 联网搜索与学习
   - 在 GitHub、学术论文平台（如 arXive Papers with Code）、量化交易社区（如 QuantConnect、JoinQuant、BigQuant 等）搜索近期活跃或高 Star 的量化交易开源项目。
   - 重点关注以下方向：因子挖掘方法、回测框架设计、交易策略实现、风险控制模型、数据处理管道、机器学习/AI 在量化交易中的应用、实盘交易接口设计等。
   - 挑选 1-3 个最有借鉴价值的项目，深入阅读其核心代码和设计思路，总结关键亮点与可借鉴之处。

2. 项目优化思考
   - 结合学习成果，对照 jingni-trader 的现有代码结构，分析哪些模块存在改进空间。
   - 从以下角度评估优化可行性：
     - 回测引擎的准确性与性能
     - 因子库的可扩展性
     - 策略编写 API 的易用性
     - 风险管理的完善程度
     - 数据获取与处理效率
     - 代码架构的合理性与可维护性

3. 代码验证与测试
   - 对经过评估确实有价值的优化方向，编写验证代码进行实际测试。
   - **基于 main 分支创建新分支进行开发**，分支命名规则：feat/quant-opt-YYYYMMDD（其中 YYYYMMDD 为当次执行日期，例如 feat/quant-opt-20260610）。
   - 所有新代码必须位于该新分支的独立文件或目录中，不直接修改 main 分支的代码。
   - 验证内容包括但不限于：正确性测试、性能对比测试、边界条件测试。
   - 生成验证报告，包含：优化点说明、借鉴来源、测试代码、测试结果、对比分析。
   - 测试完成后，将该新分支自动推送到 GitHub 远程仓库（仅 git push，不合并）。

4. 汇报
   - 将每次的学习成果、优化思考和测试结果整理成清晰的报告输出。
   - 报告需包含：学习项目清单及核心亮点、可借鉴的方向列表、已完成的验证测试及结论、待用户确认的优化建议。
   - 保存报告到本地文件系统中，便于用户随时查阅。

重要约束：
- 所有优化代码在用户明确确认之前，绝对禁止执行 git merge 操作合并到 main 分支。
- 允许在自动化任务流程中自动创建新分支（feat/quant-opt-YYYYMMDD）并推送到 GitHub，但**不合并**。
- 用户确认优化方案后，会主动告知你可以合并到 main，届时方可执行 git merge / PR 合入操作。
- 编译、测试、git push 分支等操作不受此限制。
