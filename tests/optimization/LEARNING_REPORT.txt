一、学习项目清单及核心亮点
================================================================================

本次学习聚焦了三个高价值量化交易开源项目，覆盖 AI 因子挖掘、高性能回测引擎、
模块化交易平台三个维度。以下是深度分析结果。

┌──────────────────────────────────────────────────────────────────────────────┐
│  项目1: Microsoft Qlib                                                       │
│  GitHub: https://github.com/microsoft/qlib                                   │
│  Stars: ~44,000  |  语言: Python  |  维护状态: 活跃                          │
└──────────────────────────────────────────────────────────────────────────────┘

核心亮点:

1. Point-in-Time 数据库
   - 设计初衷: 防止回测中因使用未来修正数据导致的数据泄露
   - 实现方式: 每个因子值关联 publish_date（发布日），查询时仅返回 query_date
     前发布的最新版本
   - 价值: PIT 违规可能导致因子值差异高达 50%+（见验证测试），直接导致
     回测结果虚高、实盘表现崩塌
   - 对 jingni-trader 的启示: 当前纯量价因子不存在泄露问题，但如果未来引入
     财务数据因子（ROE, PE, PB等），必须实现 PIT 逻辑

2. 因子表达式引擎
   - 设计思想: 声明式因子定义，通过表达式组合基础因子，支持 cs_rank, zscore
     等截面运算
   - 内置 Alpha158 因子集: 158 个经典量化因子，覆盖动量、估值、质量等维度
   - 表达式缓存系统: 避免重复计算，提升批量因子生成性能
   - RD-Agent 集成: 基于 LLM 自动挖掘因子、优化模型

3. 高性能数据存储
   - 列式二进制格式替代传统行式存储(Pandas/HDF5)
   - 时间主轴 + 列式结构，读取性能优于 MySQL、MongoDB、InfluxDB
   - Purged Group Time Series Split: 带清洗期的时序交叉验证，防止过拟合

4. 模型 Zoo
   - 20+ 预置模型: LightGBM, XGBoost, LSTM, GRU, Transformer, GATs, TFT
   - 多范式支持: 监督学习、市场动态建模、强化学习
   - 统一接口: 模型训练/评估/回测一气呵成

   - 90% 内存优化
   - 自动回退机制: Rust 不可用时无缝切换到 Python 实现

2. 零拷贝数据桥接 (QADataBridge)
   - 基于 Apache Arrow 的跨语言零拷贝数据传输
   - Pandas ↔ Polars (2.5x 加速)
   - 共享内存通信 (7x 加速)

3. QIFI 统一账户协议
   - 跨语言标准数据结构，Python/Rust/C++ 保持一致
   - 研究环境到生产环境无缝切换

4. 全栈式量化金融分析框架
   - 数据获取 → 因子研究 → 策略回测 → 实盘交易
   - 微服务架构，支持分布式部署

二、可借鉴的方向列表（对照 jingni-trader 现状分析）
================================================================================

┌──────┬──────────────────────────────────┬────────────────────┬──────────────┐
│ 优先级 │ 优化方向                          │ 借鉴来源            │ 预期收益      │
├──────┼──────────────────────────────────┼────────────────────┼──────────────┤
│ ★★★  │ 1. 向量化回测引擎                  │ QUANTAXIS、Rust实践 │ 33-125x加速   │
│ ★★★  │ 2. Point-in-Time 数据安全层        │ Qlib               │ 消除未来泄露  │
│ ★★☆  │ 3. 因子表达式引擎（声明式因子定义）  │ Qlib               │ 10x开发效率   │
│ ★★☆  │ 4. 多模型支持（LSTM/Transformer等） │ Qlib               │ 策略多样性    │
│ ★★★  │ 5. 因子缓存系统                     │ Qlib、QUANTAXIS    │ 避免重复计算  │
│ ★☆☆  │ 6. Python+Rust 混合加速             │ QUANTAXIS          │ 更高性能上限  │
│ ★★☆  │ 7. 模块化事件驱动架构               │ vnpy               │ 可维护性提升  │
│ ★☆☆  │ 8. 数值常量支持（表达式引擎）        │ Qlib               │ 更灵活配置    │
└──────┴──────────────────────────────────┴────────────────────┴──────────────┘

详细分析:

1. 向量化回测引擎 (★★★★★)
   当前问题: NativeAdapter 使用逐日逐股 for 循环，在大规模回测场景下性能
            瓶颈明显。200只股票、2年日线数据需要 3.4 秒。
   优化方向: 用 NumPy 矩阵运算替代循环，预计算权重矩阵，批量计算净值。
   验证结果: 平均加速 89.6x，最高 125x（200stocks_504days: 3.42s → 0.027s）
   风险: 低。纯计算优化，不影响策略逻辑正确性。

2. Point-in-Time 数据安全层 (★★★★★)
   当前问题: 仅使用量价因子时不存在泄露风险。但如果未来引入财务数据因子
            (ROE/PE/PB等)，会面临严重的未来数据泄露问题。
   优化方向: 实现类似 Qlib 的 PIT 数据接口，确保因子计算只用历史可得数据。
   验证结果: 在模拟含财务修正的测试中，PIT违规导致 8% 平均偏差，最高 54%。
   风险: 中。需要重构数据层，但可分阶段实现（先用量价因子保证安全）。

3. 因子表达式引擎 (★★★★☆)
   当前问题: 因子全量硬编码在 compute_a_share_factors() 中，新增因子需修改
            核心代码，缺乏配置化和可组合性。
   优化方向: 实现声明式因子定义（JSON/YAML 配置），支持表达式组合和截面运算。
   验证结果: 表达式引擎计算的因子与硬编码版本完全一致（correlation=1.0），
            通过配置驱动即可生成 11->14 个因子的扩展集。
   已知限制: 数值常量、复杂嵌套表达式支持待完善。

4. 多模型支持 (★★★☆☆)
   当前问题: strategy-model-engine 仅支持 LightGBM/CatBoost/Logistic/RF，
            缺少深度学习模型（LSTM/Transformer）和 GNN 模型。
   优化方向: 参考 Qlib Model Zoo，集成 20+ 预训练模型，统一训练/评估接口。
   验证: 暂未实施验证代码（需安装 torch/tf 等大量依赖）。

5. 因子缓存系统 (★★★★★)
   当前问题: factor-engine 每次 run() 都重新计算全部因子，没有缓存复用。
   优化方向: key=(因子名, 数据hash, 参数hash) → value=(计算结果) 的缓存层。
   验证: 表达式引擎原型已内置 _cache 字典，实测命中后速度提升显著。

6. Python+Rust 混合加速 (★★☆☆☆)
   当前问题: 内核计算密集型操作（回测循环、因子批量计算）受 Python GIL 限制。
   优化方向: 参考 QUANTAXIS QARSBridge，用 PyO3 将热路径用 Rust 重写。
   风险: 高。引入 Rust 编译工具链，增加构建复杂度。建议先做向量化优化。

7. 模块化事件驱动架构 (★★★☆☆)
   当前问题: 子 Skill 之间通过文件系统传递产物（.parquet/.json），耦合度较高。
   优化方向: 参考 vnpy 的事件驱动引擎，实现内存中事件总线传递数据。
   风险: 低。可渐进式引入，先在不影响现有流程的模块试点。

8. 数值常量支持 (★★☆☆☆)
   当前问题: 表达式引擎原型未支持数值常量（如 `rsi_14 - 50` 无法解析）。
   优化方向: 在表达式解析器中加入字面量识别。

测试2.1 - 财务数据修正与PIT泄露演示:
  - 含修正的财报记录: 114 条
  - 存在泄露差异的记录: 80/120 个截面
  - 平均因子值差异: 8.19%
  - 最大因子值差异: 53.95%
  - 结论: 如果不使用PIT，回测中使用修正后财务数据会导致严重的过度乐观

测试2.2 - jingni-trader 因子计算泄露检测:
  - ✓ pct_change(1): SAFE - 仅依赖历史数据
  - ✓ rolling(20): SAFE - 仅依赖 t-19..t 数据
  - → forward_return: EXPECTED - 作为标签使用未来信息是合法的
  - ⚠ bfill填充: WARNING - 跨时间反向填充会引入未来泄露

测试2.3 - PIT因子构建器原型:
  - SimplePITFactorBuilder 正确实现了时间安全查询
  - 不同查询时间点返回的数据版本一致（无泄露）
  - 原型可直接扩展用于财务因子构建

结论: 当前量价因子不存在泄露风险，但需警惕 bfill/ffill 的使用。
      引入财务数据因子时必须实现 PIT 逻辑。
